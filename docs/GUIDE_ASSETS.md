## 1. 准备环境

两种方式任选其一：**方式一：下载包**（推荐新手，不需要 Git，不需要敲命令）；**方式二：开发者**（git clone，见 1.2 起）。

### 方式一：下载包（推荐新手）

1. 安装 Node.js 22 或更高版本（LTS），见下面的 1.1。
2. 打开 <https://github.com/SKT0tto/OpeNotes-Studio/releases/latest>，下载 `OpeNotes-Studio-v版本号.zip`。
3. 解压到任意目录（路径里尽量不要有空格）。
4. **Windows**：双击 `Start-Windows.cmd`。**macOS / Linux**：在终端进入解压目录运行 `./start.sh`（没有执行权限时用 `bash start.sh`）。
5. 第一次运行会自动安装依赖（需要联网，几十秒）。随后会问：「需要 Live2D Cubism Core 才能显示 Live2D 模型……是否同意协议并从 Live2D 官方下载？[Y/n]」——同意《Live2D 专有软件许可协议》就输入 `Y` 回车，它只会从 Live2D 官方地址下载；输入 `N` 也可以，之后在网页的配置向导里还会再提示。
6. 浏览器会自动打开 <http://127.0.0.1:5274>，按首页的**配置向导**导入素材（见第 2 章起）。使用期间请保持启动窗口开着，关闭它就会停止服务。

升级：先关闭程序，双击 `Update-Windows.cmd`（macOS / Linux：`bash update.sh`）自动更新——它只替换有变化的文件，`data/`、`.env`、`studio.config.json`、`vendor/` 不会被改动，旧文件备份在 `update-backup/`，加 `--rollback` 可还原（更新脚本从 1.0.0 之后的版本开始内置，旧版需先手动下载一次）。也可以把新版本解压**覆盖**到旧目录，保留 `data/`（项目与设置）和 `studio.config.json`（素材库路径）。下载包不含任何游戏素材，也不含 Cubism Core。

> 方式一不需要看 1.2、1.3，直接跳到[第 2 章](#2-首页与配置向导)。

### 方式二：开发者（git clone）

### 1.1 安装 Node.js

1. 打开 <https://nodejs.org/>，下载 **LTS** 版本（要求 22 或更高，作者使用 24）。
2. 一路「下一步」安装。安装后打开 PowerShell（Windows）或终端（macOS / Linux），输入：

   ```
   node -v
   npm -v
   ```

   能看到版本号（`v22.x` 或更高）就说明装好了。

### 1.2 安装 Git 并克隆仓库

1. 从 <https://git-scm.com/> 安装 Git（不想装 Git 也可以在 GitHub 页面点「Code → Download ZIP」，解压后跳到 1.3）。
2. 选一个你喜欢的目录（路径里尽量不要有空格和中文），执行：

   ```
   git clone https://github.com/SKT0tto/OpeNotes-Studio.git openotes-studio
   cd openotes-studio
   ```

### 1.3 安装依赖并启动

```
npm install
npm run dev
```

- `npm install` 第一次需要几分钟，会安装前端和后端依赖。
- `npm run dev` 同时启动服务端（`127.0.0.1:5274`）和前端（`127.0.0.1:5273`）。看到两边都输出「ready」后，用浏览器打开 **<http://127.0.0.1:5273>**。
- 要停止，在那个终端里按 `Ctrl+C`。

> 第一次打开时素材库是空的，页面会自动进入**配置向导**，这是正常的。

## 2. 首页与配置向导

首页右侧有一张「环境检查」卡片，列出三项状态：

| 项目 | 绿色表示 | 点击按钮 |
|---|---|---|
| 素材库 | 已有模型与背景（显示数量） | 「导入素材」/「导入更多素材」 |
| Cubism Core | Core 已加载，支持 moc3 v5 | 「获取 Core」/「管理 Core」 |

1. **Cubism Core**
2. **导入素材**
3. **AI（可选）**：不配置也能用「规则导演（非 AI）」。

向导随时可以重新打开：首页 → 「配置向导」。

## 3. 第 1 步：获取 Cubism Core

Live2D 模型需要 Live2D 公司的 **Cubism Core 5.x** 才能渲染。它是专有软件，本项目不包含、不分发。

### 方式 A：什么都不做（默认）

程序默认在浏览器里直接从 **Live2D 官方地址**加载 Core。联网时向导第 1 步会显示「Cubism Core 已加载（支持 moc3 v5）」，这一步就完成了。

### 方式 B：一键保存一份到本机（离线使用 / 官方地址打不开时）

1. 向导 → 第 1 步。
2. 点「Live2D 专有软件许可协议」链接，阅读后勾选「我已阅读并同意…」。**不勾选，下面两个按钮都是灰的。**
3. 点「**从 Live2D 官方获取并保存到本地**」。服务端只会访问 Live2D 官方地址，不使用任何镜像；文件保存到仓库下的 `vendor/live2dcubismcore.min.js`（已被 git 忽略，不会被提交）。
4. 程序会立刻加载它并检查是否支持 moc3 v5。通过后状态显示「来源：本地副本 vendor/」；不通过则自动退回官方地址并给出原因。
5. 想退回官方地址：点「改回官方地址」。

### 方式 C：官方地址用不了，自己选文件

1. 点「打开官方 SDK 下载页」，在 Live2D 官网下载 **Cubism SDK for Web**，解压。
2. 在解压出来的目录里找到 `live2dcubismcore.min.js`（通常在 `Core` 文件夹下）。
3. 回向导，勾选许可协议，点「选择本地的官方文件…」选中它。
4. 程序只检查文件头里的 Live2D 声明和版本入口，不内置任何哈希。

> 上传其它任意 js 文件会被拒绝（提示「不是 Live2D Cubism Core」）。这是预期行为。

## 4. 第 2 步：准备素材

### 4.1 先看素材库需要什么

素材库就是一个文件夹（默认仓库下的 `assets/`，已被 git 忽略），结构是：

```
assets/
  models/<模型id>/model3.json, model.moc3, physics3.json, textures/…, motions/…, expressions/…
  backgrounds/<背景id>.png
```

- 模型 id 就是文件夹名，例如 `001_casual_spring_01`（`001` 是角色，后面是服装）。
- 背景 id 有两种：剧情背景 `adv_bkg_stage_000001`，名片背景是数字 `1`–`28`。它们和 `asset-labels/backgrounds.json` 里的标签（属于哪个乐队、是什么地点）一一对应，id 对不上就会被当成「未知背景」。
- 你**不需要自己整理成这个结构**：本地导入会帮你整理，见 4.4。

素材要由你自己合法取得。常见来源是你自己从游戏中提取的资源，或者你有权使用的网站下载包。

### 4.2 用「素材清单」知道缺什么（可选）

如果你打算从 Haneoka 站点（`haneoka.org`，一个第三方的游戏数据库网站）手动下载，可以先让程序告诉你缺哪些。

1. 向导 → 第 2 步 → 顶部页签「**素材清单（Haneoka，仅清单）**」。
2. 第一次会显示**免责声明**：素材权利归 Bushiroad / Craft Egg 等；Haneoka 的使用条款禁止未经许可下载再利用；本功能只读公开元数据、只生成链接清单、**不下载任何素材**；是否下载由你自己决定并自己负责。文字滚到底部后，「我已阅读并同意」才能点。
   - 这个确认是在**服务端**强制的：没确认之前，清单相关接口一律返回 403；免责声明文字更新后需要重新确认。
3. 确认后程序读取站点公开的三个索引（模型、剧情背景、名片背景）。**只有 3 个请求**，带说明项目名称和仓库地址的 User-Agent，结果缓存 24 小时，之后再打开不会重复请求；也不会逐文件探测。
4. 页面左边是模型树：乐队 → 角色 → 服装；右边是背景列表，可按「全部 / 剧情背景 / 名片背景」筛选，或按 id、地点、乐队搜索。
   - 默认勾选「只显示本地没有的」；「显示低模（_low）」默认关闭。
   - 背景旁边会显示项目已有的标签（地点、乐队）；显示「无标签」的背景导入后会按「未知」处理。
5. 勾选你想要的，点「**生成清单（N）**」。清单里每一项都有「在站点打开」链接，指向 Haneoka 的**页面**（不是素材文件直链）。
6. 点「导出 Markdown」或「导出 CSV」可以保存清单，方便对照着一项项下载。清单里同样只有页面链接。

> 清单里的站点语言可以在「站点语言」下拉框里选（en / ja / ko / zh-CN / zh-TW），只影响链接指向的页面语言。

### 4.3 在 Haneoka 站点上手动下载

下面的页面结构是在编写本教程时实际打开站点核对的（2026-10）。站点可能改版，**以站点当时的界面为准**；如果界面变了，找不到按钮时，到站点首页用它的导航和搜索即可。

**请低频访问**：一次只开几个页面，不要用脚本、下载器或批量工具。素材由你手动下载，并自行确认你有权使用、遵守站点条款。

#### 模型

1. 打开清单里的链接，格式是：
   `https://haneoka.org/intl/<语言>/live2d/<模型id>/`
   例如 `https://haneoka.org/intl/zh-CN/live2d/001_casual_spring_01/`（页面标题会显示角色名和服装）。id 写错会得到 404。
2. 这是站点的 **Live2D 查看器**页面。站点界面里下载按钮的文字是「**Download model ZIP**」（英文界面；其他语言界面里是对应翻译）。点它，把 ZIP 保存到你自己的下载目录，比如 `D:\Downloads\haneoka\`。
3. 同一个角色有不同服装（`casual`、`school`、`live-mode`…）和低模（`_low`）。多数情况下你只需要标准模型，不需要 `_low`。
4. **不要解压也可以**：本地导入直接支持 zip。

#### 名片背景（数字 id）

1. 打开 `https://haneoka.org/intl/<语言>/backgrounds/<数字id>/`，例如 `…/backgrounds/14/`（标题是名片背景的名称）。
2. 页面里能看到背景图。在图片上右键 →「图片另存为」，保存成 **`14.png`**（文件名必须是数字 id）。

#### 剧情背景（`adv_bkg_stage_NNNNNN`）

- 这类背景没有单独的详情页（实测 `…/backgrounds/adv_bkg_stage_000001/` 是 404）。清单里它们链接到站点的**资源浏览页** `https://haneoka.org/intl/<语言>/assets/`。
- 在资源浏览页里查找名为 `adv_bkg_stage_000001` 的项，保存其图片，文件名一定要改成 **`adv_bkg_stage_000001.png`**。资源页是网页端的资源浏览器，具体怎么搜索 / 展开以站点当前界面为准。
- 取不到某一张也没关系：缺的背景只是在资源浏览器里看不到，不影响其他内容。

> 文件名就是 id。命名不规范的图片导入时会显示「无法识别」，你可以直接在预览表格里填 id，不用重新命名。

下载完成后，建议把所有下载物放进**同一个文件夹**，比如：

```
D:\Downloads\haneoka\
  001_casual_spring_01.zip
  14.png
  adv_bkg_stage_000001.png
```

### 4.4 本地导入

1. 向导 → 第 2 步 → 页签「**本地导入**」。
2. 选择素材，两种方式：
   - 在输入框里粘贴文件夹或 `.zip` 的**绝对路径**（如 `D:\Downloads\haneoka`），点「**扫描**」；
   - 或点「**上传 .zip…**」直接选择一个 zip。
   - 文件夹里的 zip 不会被自动展开；一个 zip 一次导入。如果你有好几个 zip，先把它们解压到同一个文件夹，再扫描这个文件夹。
3. 等待分析。程序会计算每个文件的 SHA-256、检查 PNG 文件头和 `MOC3` 文件头，并把每个模型整理成本项目的结构。
4. 看**导入预览**：

   | 位置 | 含义 |
   |---|---|
   | 顶部一行 | 模型数 / 背景数 / 动作数 / 表情数 / 将写入的文件数和大小 |
   | 状态「新增」 | 素材库里没有，会导入 |
   | 状态「已存在（相同）」 | 内容完全一致，自动跳过（增量导入） |
   | 状态「已存在（不同）」 | id 相同但内容不同，**默认跳过**；勾选「覆盖…」才会替换 |
   | 状态「错误」 | 如缺少纹理、文件头不对，不会导入，原因写在备注里 |
   | 状态「无法识别」（背景） | 文件名不符合规则，在输入框里填 id 后点「应用 id 并重新分析」 |
   | 备注「已规范化」 | 模型是站点格式，已自动转换（见下） |
   | 背景「已有标签」 | id 和 `asset-labels/backgrounds.json` 对上了 |
   | 「跳过 N · 错误 N」折叠区 | 被跳过的文件和错误清单 |

5. 点「**导入 N 项**」。完成后显示报告：导入了几个模型、几张背景、多少动作和表情，跳过与错误清单。点「在资源浏览器中查看」就能看到刚导入的内容。

**自动规范化是什么？** 从站点下载的 `model3.json` 有两个问题：贴图写成站点上的绝对路径，所有动作都放在同一个「Motion」组里。直接用的话，项目只能索引到 1 个动作，而且**不会报错**。导入时程序会：

- 按文件名找到贴图，复制到 `textures/` 并改成相对路径；
- 把大组拆开，每个动作一组，组名就是动作文件名；
- 检查 moc3 文件头，缺文件就报错。

规范化的结果写进素材库里的**副本**，你的原文件一个字节都不会改。导入后报告里的「动作数」应该等于原包里的动作条目数（例如 64 个）。

**再导一次会怎样？** 相同内容全部显示「已存在（相同）」并跳过，导入按钮变成「导入 0 项」。所以可以放心地增量导入：下载了新的模型，把它放进同一个文件夹，再扫描一遍即可。

**模型 id 不对？** 预览备注里写着「无法从目录名识别模型 id」的行，id 列是可以编辑的输入框；改好后点「应用 id 并重新分析」。

### 4.5 整包素材包（native layout + openotes-pack.json）

如果你已经有一个完整的素材库（比如从旧版本迁移，或者在另一台电脑上），可以把它整个打成一个 zip，在向导里一键导入。**这种包不需要任何规范化**，导入器会直接按原样写入。

**打包**（在已有素材库的那台电脑上，仓库目录里执行）：

```
npm run pack-assets -- --out D:\packs\openotes-assets.zip
```

- 读取当前配置的素材库（`ASSET_ROOT`），也可以用 `--root <目录>` 指定；
- 输出 zip **不能写在仓库目录内**，已存在的文件不会被覆盖；
- 会逐个文件计算 SHA-256，并写入 zip 根目录的 `openotes-pack.json`；
- 流式写入，不会把整个文件读进内存；超过 4 GB 自动使用 ZIP64；`.png` 等已压缩格式用存储方式，其余用 deflate。

**包的结构**（以下内容放在 zip 根目录，或放在**唯一的一层**外包目录里，两种都能识别）：

```
openotes-pack.json        可选的描述文件（见下）
manifest.json             可选，旧版素材清单（中文名、背景描述等元数据）
models/<模型id>/model3.json, model.moc3, physics3.json, textures/…, motions/…, expressions/…, preview.png
backgrounds/<背景id>.png
media/…                   音频等，保持相对路径
```

**`openotes-pack.json` 字段**（可选；存在时导入器会校验，格式见 `shared/schema/pack.ts`）：

| 字段 | 含义 |
|---|---|
| `format` | 固定为 `"openotes-pack"` |
| `version` | 固定为 `1` |
| `generatedAt` | 生成时间（ISO 8601） |
| `generator` | 可选，生成工具说明 |
| `counts` | `{ "models": N, "backgrounds": N, "media": N }`，与包内实际数量比对 |
| `totalBytes` | 所有文件的总字节数 |
| `files` | 可选；`[{ "path": "models/001_x/model.moc3", "bytes": 123, "sha256": "…64 位十六进制…" }]`，路径相对包根目录。给出时逐个校验大小和 SHA-256 |

校验不通过（数量不符、文件缺失、大小或哈希不一致、描述文件格式错误）时，预览里会用红字列出，并且**禁止导入**，避免把损坏的文件写进素材库。没有这个文件时按普通素材导入处理。

**导入大包**：向导 → 第 2 步 → 本地导入 → 填入 zip 的绝对路径 → 「扫描」（不要用「上传 .zip」导入几个 GB 的包，直接用路径更快）。程序会先流式解压到 `data/import-tmp/`（需要与包等大的临时空间），再校验、再写入。页面上有进度条和「取消」按钮；取消或失败会清理临时文件，已经写入完成的模型保留。重复导入同一个包，内容相同的文件全部跳过。

#### 把素材库放到别的磁盘

默认导入目标是仓库下的 `assets/`。要换：展开页面底部「素材库位置」→ 输入新的绝对路径 → 「保存位置」。目录必须可写。程序会写进 `studio.config.json`（`assetRoot`），**需要重启**服务端（终端里 `Ctrl+C` 再 `npm run dev`）才生效。如果你设置了环境变量 `ASSET_ROOT`，它优先于配置文件。

#### 在资源浏览器里确认

首页顶部导航或向导里的「在资源浏览器中查看」会打开 `/assets`。这里可以按角色、乐队筛选，查看模型的动作与表情、背景和它们的标签。想确认模型真的能渲染，打开 `/lab/actor`（Actor Lab）：选择刚导入的模型，应该能看到角色并在播放待机动作。

## 5. 第 3 步：配置 AI（可选）

首页右上角「AI 设置」，或向导第 3 步的「打开 AI 设置」。选择一个提供商，填好后点「**测试连接**」，成功了再保存使用。**Key 只保存在本机 `data/settings.local.json`，不会上传、不会入库，界面只显示掩码**（如 `sk-…087b`）。留空 Key 框表示保留已保存的那个。

### Claude（Anthropic）

1. 提供商选 **Claude（Anthropic）**。
2. 在 <https://console.anthropic.com/> 创建 API key，粘贴到「Key」。
3. 模型默认 `claude-sonnet-5-5`，一般不用改。
4. 也可以不在界面填，而是设置环境变量 `ANTHROPIC_API_KEY`。

### OpenAI 兼容接口（DeepSeek、其他云服务）

1. 提供商选 **OpenAI 兼容**。
2. 「接口地址」填服务商的 base URL，「模型」填服务商的模型名，「Key」填你的 key。
3. DeepSeek：接口地址 `https://api.deepseek.com`，模型名按 DeepSeek 官方文档填写（如 `deepseek-chat`），Key 在 DeepSeek 开放平台创建。
4. 其他兼容服务（vLLM 等）同理。

### LM Studio（本地模型）

1. 在 LM Studio 里加载一个模型，打开「Developer / Local Server」，启动服务（默认端口 1234）。
2. 提供商选 **OpenAI 兼容**，接口地址填 `http://localhost:1234/v1`，模型名填 LM Studio 里显示的模型标识，Key 可以留空。
3. 本地小模型对格式要求的遵循能力参差不齐，如果生成失败可以换更大的模型，或者改用「规则导演（非 AI）」。

### 没有 Key 也能用

在「AI 拆解」对话框或编辑器的「AI 导演」页签里选择「**规则导演（非 AI）**」：按章节和时间词分场、按关键词匹配背景与服装、识别引号台词和说话人，使用固定镜头节奏。它产出的内容都标成「规则」，不会假装是 AI。

## 6. 导入小说，一键生成

1. 回到首页，点大卡片「**导入小说，一键生成**」（也叫「AI 拆解…」）。
2. 粘贴文字，或打开 `.txt` / `.md` 文件。支持 UTF-8 和 GBK（自动识别），识别 `第一章`、`# 标题` 这样的章节。想先试试，仓库里有示例 `examples/mygo-rehearsal.txt`（原创文本）。
3. 选择导演方式（AI 或规则导演），点「**一键生成完整演出**」。程序先拆解分场、选背景和服装，创建项目，再逐场导演（一次 3 场），显示进度、调用次数和耗时。随时可以取消，之后点「继续生成剩余场景」会接着做（已完成的场景有缓存，不会重复花钱）。
4. 完成后会列出连贯性警告（例如角色服装前后不一致）。点「放映」直接播放（`/play/<项目id>`，可选 16:9 或 2.16:1 画幅），或点「在编辑器中精修」。

> 没有素材的角色或背景会在拆解时被避开或提示；素材库越全，效果越好。背景没有标签时按「未知」处理，AI 只会在没有更合适选择时才用它。

## 7. 编辑、锁定与重新生成

编辑器分为大纲 / 脚本、舞台预览、时间轴、检查器等区域。

- **逐句修改**：点中一句台词，在右侧检查器里改说话人、表情、动作、镜头、站位、文字等。舞台上也有取景和站位工具。改动会记在当前播放头位置的关键帧上。
- **撤销 / 重做**：`Ctrl+Z` / `Ctrl+Y`（或 `Ctrl+Shift+Z`）；`Ctrl+S` 保存。
- **来源标记**：每处内容都标明来自「AI」「规则」还是「手动」。你改过的内容会被标成「手动」。
- **锁定**：检查器里字段旁边有锁图标，点一下就锁定。**锁定的内容，重新生成永远不会覆盖。**
- **重新生成**：「AI 导演」页签里选择范围（镜头、表演、服装、站位、特效，或只重做选中的一句），生成的结果以**差异对比**（改前 → 改后）显示，你可以全部接受、只接受某些范围，或拒绝。接受是一次撤销步骤。默认不会覆盖你手改过的内容；要覆盖需要勾选「也覆盖我手改过的内容」，但锁定的永远不会被覆盖。
- **导出分享**：顶部「导出」得到 `.openotes.json`。导出文件只含项目数据和素材 id，**不含任何素材文件**，对方需要自己的素材库才能播放。

## 8. 常见问题排错

| 现象 | 原因与办法 |
|---|---|
| 页面空白或「服务端不可用」 | 终端里 `npm run dev` 没在运行，或端口被占用。重启；看终端里的报错。 |
| 向导第 1 步红字，Core 加载失败 | 联网检查官方地址；或用 3 方式 B / C 保存一份本地副本。公司网络可能拦截，换网络或用方式 C。 |
| 提示 Core 太旧、需要 5.x | 你选的不是官方最新的 `live2dcubismcore.min.js`。到官网重新下载 Cubism SDK for Web。 |
| 导入后模型只有 1 个动作 | 素材没有经过导入向导，直接复制了站点的 `model3.json`。用向导重新导入；或检查 `model3.json` 里 `Motions` 是不是只有一个组。 |
| 导入提示「找不到纹理」 | 下载包不完整，纹理 png 不在你选的文件夹 / zip 里。把所有文件放在同一个文件夹后重扫。 |
| 提示「不是有效的 moc3 文件」 | 文件损坏或下载到的是网页而不是模型。重新下载。 |
| 背景显示「无法识别」 | 文件名不是 id。在预览表格里填 `adv_bkg_stage_000001` 或数字 id，点「应用 id 并重新分析」。 |
| 背景「无标签（按“未知”处理）」 | 站点新增了本项目还没标注的背景，或 id 不对。可以在资源浏览器里手动标注。 |
| 提示 zip 不安全 / 超过上限 | zip 里有越界路径、符号链接、仅大小写不同的重名文件，或解压后超过大小上限（默认 16 GB，可用 `IMPORT_MAX_BYTES` 调整）。换一个干净的压缩包。 |
| 提示「已存在（不同）」 | 素材库里已有同 id 但内容不同的模型。默认保留旧的；确认要替换再勾选「覆盖…」。 |
| 素材清单返回「无法读取站点索引」 | 站点暂时不可用或接口变化。稍后再试，或直接打开 `haneoka.org` 手动查找；本地导入不受影响。 |
| 保存了新的素材库位置，但没变化 | 要重启服务端；另外检查环境变量 `ASSET_ROOT` 是否覆盖了配置。 |
| AI「测试连接」失败 | 检查 Key、接口地址、模型名；LM Studio 要确认服务已启动且地址以 `/v1` 结尾；国内网络访问 Claude / OpenAI 可能需要代理。 |
| 生成中途失败 | 点「继续生成剩余场景」，已完成的不会重做。 |
| 某句台词的背景 / 服装不合适 | 在检查器里手动改，并锁定，再重新生成别的内容。 |

还不能解决：把终端里的报错和你的操作步骤发到仓库的 Issues（<https://github.com/SKT0tto/OpeNotes-Studio/issues>），**不要上传素材文件，也不要贴出 API key**。
